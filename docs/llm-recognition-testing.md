# LLM语义识别专项测试指南

## 📋 概述

本测试套件专门用于验证**LLM的语义理解能力**，包括：
- 自然语言理解
- 同义词识别
- 语序变化处理
- 隐含意图识别
- 复杂语句解析
- 与规则匹配的对比

## 🔍 **测试示例**

### **示例1：口语化表达**

**输入**：
```
"帮我把那个学号是S001的同学删掉呗，谢谢啦！"
```

**LLM理解**：
```json
{
  "intent": "DELETE",
  "action": "deleteStudent",
  "params": {
    "stuNo": "S001"
  },
  "confidence": 0.92
}
```

**规则匹配**：
```
❌ 无法识别（过于口语化）
```

**结论**：LLM表现更好 ✅

---

### **示例2：隐含意图**

**输入**：
```
"这个学生已经毕业了，不需要再保留他的信息了"
```

**LLM理解**：
```json
{
  "intent": "DELETE",
  "action": "deleteStudent",
  "params": {},
  "confidence": 0.75,
  "note": "需要进一步确认要删除哪个学生"
}
```

**规则匹配**：
```
❌ 无法识别（没有明确的"删除"关键词）
```

**结论**：LLM能理解隐含意图 ✅

---

### **示例3：复杂多条件**

**输入**：
```
"帮我创建一个新的员工记录，工号是E2024001，名字叫张三，今年30岁，职位是教授，邮箱是zhangsan@university.edu.cn"
```

**LLM提取**：
```json
{
  "intent": "CREATE",
  "action": "addEmployee",
  "params": {
    "empNo": "E2024001",
    "empName": "张三",
    "age": 30,
    "position": "教授",
    "email": "zhangsan@university.edu.cn"
  },
  "confidence": 0.95
}
```

**规则匹配**：
```
⚠️  只能提取部分字段（工号、姓名）
```

**结论**：LLM参数提取更全面 ✅

## 💡 **优化建议**

### **基于测试结果的建议**

#### **1. 使用场景推荐**

| 场景 | 推荐模式 | 原因 |
|------|---------|------|
| 简单明确指令 | 规则匹配 | 速度快，成本低 |
| 口语化表达 | LLM优先 | 理解能力强 |
| 复杂多条件 | LLM优先 | 参数提取全面 |
| 隐含意图 | LLM优先 | 能理解上下文 |
| 生产环境 | 混合模式 | 平衡速度和准确性 |

#### **2. Prompt优化**

如果LLM识别效果不理想，可以优化System Prompt：

```java
// 在 IntentRecognitionService.java 中
private static final String SYSTEM_PROMPT = 
    "你是紫金学院管理系统的智能助手..." +
    // 添加更多示例
    "用户说'帮我把XXX删掉' → 理解为删除操作\n" +
    "用户说'我不想要XXX了' → 理解为删除操作\n";
```

#### **3. 置信度阈值调整**

```java
// 当前阈值：0.7
if (llmResult.getConfidence() > 0.7) {
    // 使用LLM结果
} else {
    // 降级到规则
}

// 可以根据测试结果调整
// 更严格：0.8（减少误判）
// 更宽松：0.6（更多使用LLM）
```

## 🔧 **故障排查**

### **问题1：所有测试都跳过**

**原因**：API_KEY未配置

**解决**：
```java
private static final String API_KEY = "your-actual-api-key";
```

---

### **问题2：LLM调用超时**

**原因**：网络问题或API服务繁忙

**解决**：
1. 检查网络连接
2. 增加超时时间
3. 稍后重试

---

### **问题3：识别准确率低**

**可能原因**：
1. Prompt不够清晰
2. 模型选择不当
3. 置信度阈值过高

**解决**：
1. 优化System Prompt，添加更多示例
2. 尝试不同的模型（如glm-4-plus）
3. 降低置信度阈值（从0.7降到0.6）

---

### **问题4：API配额不足**

**症状**：返回429错误或配额耗尽提示

**解决**：
1. 检查API账户余额
2. 申请更高配额
3. 使用缓存减少重复调用
4. 切换到免费额度更多的提供商
